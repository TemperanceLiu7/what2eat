# 上线清单（后端数据库 + 前端接真接口）

> ⚠️ **先看这条**：`render.com` / `api.render.com` / `*.onrender.com` 在国内多数网络下不可直连，
> 按本文部署出来的 API 域名大概率打不开。当前推荐按 **`docs/部署清单-Railway+Neon.md`** 部署
> （Railway + Neon 均实测可直连，新用户 30 天 $5 额度、无需信用卡）。本文保留作为 Render 的历史参考，
> 步骤 1、4、5、8 仍然适用。

> 按顺序做完这 8 步，`what2eattt.pages.dev` 就从「浏览器本地 mock」变成「真数据库」。
> 全程免费，约 20 分钟；其中 Render 构建 3~5 分钟、Pages 重新部署 2 分钟。
> 每一步都给验收标准，做完能自己确认，不用猜。

---

## 0. 先明确现在的状态

| 能力 | 现在 | 做完之后 |
| --- | --- | --- |
| 随机推荐 | mock 数据（`src/data/db.js`，写死在浏览器） | 后端 `GET /api/dishes/random/`，带权重与「避开最近 4 条」 |
| 打卡 / 点赞 / 收藏 / 投票 | 存在 localStorage，换设备就没了 | 存 PostgreSQL，换设备还在 |
| 图片识别 | 可能走的是 mock 假数据 | `POST /api/recognize/` + 你的 LLM Key |
| 多设备 / 多人 | 各自独立 | 同一份数据 |

判断当前是不是 mock：打开站点 → F12 → Network，看不到 `/api/` 请求就是 mock。

## 2. Render 建库建服务

1. 打开 <https://dashboard.render.com>，用 GitHub 登录
2. 右上角 **New +** → **Blueprint** → 选 `Ares5807/what2eat` → **Connect**
3. 页面会列出两个资源：`what2eat-db`（PostgreSQL Free）、`what2eat-api`（Web Service Free）→ 点 **Apply**
4. 弹出环境变量表单时，**只填这两项**：
   - `ADMIN_PASSWORD`：你自己定一个后台密码（不填就不建后台账号）
   - `LLM_API_KEY`：你的模型 Key（不填则识别降级为手动填菜名）
5. 等构建。日志里应依次出现：
   - `Successfully installed Django-5.2.x ...`（装依赖）
   - `... static files copied`（收集静态文件）
   - `Applying core.0001_initial... OK` → `档口 6 家 / 菜品 16 道 / 学籍 3 条`（**建表 + 灌数据**）
   - `[2/2] 后台账号 已创建后台账号 admin`
   - `Booting worker with pid`（gunicorn 起来）
   - `Live` 状态变绿

**验收**：Render 控制台服务状态是 **Live**，`Logs` 里没有 `relation "core_dish" does not exist` 之类的报错。

## 3. 验证后端

把 `<服务名>` 换成你的实际子域（形如 `what2eat-api-xxxx.onrender.com`）。

| 打开这个地址 | 期望 |
| --- | --- |
| `/api/health/` | `{"ok":true,"data":{"database":"up","dishes":16,"shops":6}}` |
| `/api/dishes/` | `{"ok":true,"data":{"items":[...]}}`，共 16 道 |
| `/api/dishes/random/?source=canteen` | 随机一道食堂菜 |
| `/api/docs/` | Swagger 文档能打开 |
| `/admin/` | 后台登录页（用第 2 步填的 admin / 密码） |

> 免费实例 15 分钟没流量会休眠，第一次打开要等 30~60 秒，属于正常现象。
> `/api/health/` 返回 503 说明库没通——直接看 Render Logs 里 `migrate` 那一段。

## 4. 前端切到真接口

1. Cloudflare 控制台 → **Workers & Pages** → 你的项目 → **Settings** → **Environment variables**
2. **Production** 加两条：

| 变量名 | 值 |
| --- | --- |
| `VITE_API_BASE` | `https://<服务名>.onrender.com/api`（**结尾不要斜杠**） |
| `VITE_USE_MOCK` | `false`（必须正好是 `false`，写 `0`/`no` 都还是 mock） |

3. **Deployments** → 最新一条右侧 `...` → **Retry deployment**
   （Vite 的变量是**构建时**注入的，不重新构建不生效）
4. 打开 <https://what2eattt.pages.dev> 硬刷新（Ctrl+Shift+R）

**验收**：
- F12 → Network 里能看到 `.../api/health/`、`.../api/dishes/random/` 的 200
- 点「抽一道」，出来的菜和 Render 后台 `/admin/core/dish/` 里的一致
- 换个浏览器/手机再抽，**收藏和打卡还在** ← 这条最关键，说明真进库了

## 5. 后台管起来（可选但建议答辩用）

`https://<服务名>.onrender.com/admin/` 里可以：
- `dishes` / `shops`：改菜名、价格、档口号（改了前端立刻生效，不用重新部署）
- `checkins`：删违规打卡
- `reports`：处理举报，可直接禁言
- `users`：看谁核验了学号

> 演示前可以手动加两道你学校真实存在的菜，比模板数据更可信。

## 6. 常见坑（都是会真实卡住的）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| Render 部署一上来就 `pre-deploy command` 报错 | 用了老版 `render.yaml`（里面还有 `preDeployCommand`） | 用本包里的 `render.yaml` 覆盖，**免费档不支持这个字段** |
| 构建成功但页面 500，日志 `relation ... does not exist` | 建表没跑 | 确认 `startCommand` 里有 `python manage.py migrate --no-input &&` |
| 前端报 `CORS` 错误 | 域名不在白名单 | Render → Environment 里 `CORS_ALLOWED_ORIGINS` 加上你的 Pages 域名（逗号分隔，无尾斜杠） |
| 前端一直 loading 或超时 | 免费实例在冷启动 | 等 30 秒再点；前端已在启动时预热 `/api/health/` |
| `/admin/` 打不开 500 | `ALLOWED_HOSTS` 没带 `.onrender.com` | 补上后重新部署 |
| 抽到的菜和 mock 时一样 | `VITE_USE_MOCK` 不是 `false`，或没重新构建 | 改值后 **Retry deployment** |

## 7. 想换更稳的数据库（Neon，可选）

Render 免费 Postgres 有有效期，答辩后一段时间会到期。想一劳永逸：

1. <https://neon.tech> 建免费项目，复制连接串（带 `-pooler` 也行，`settings.py` 已适配）
2. Render 服务 → Environment → `DATABASE_URL` 改成 Neon 的连接串
3. 保存即重启，`startCommand` 会自动把表建到 Neon 上

数据要不要迁：`python manage.py dumpdata --natural-foreign -o dump.json` 在旧库导出、
新库 `loaddata` 导入即可（Render 免费档没 Shell，这一步需要本地用同一个连接串跑）。
